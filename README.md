Выполнено:

- сохранены цены существующих карточек каталога;
- реализованы получение названий и отбор доступных туров;
- реализован поиск по названию без учёта регистра и крайних пробелов;
- реализованы фильтрация по категории и сортировка цены по возрастанию или убыванию;

- реализованы расчёт общей стоимости, количества доступных туров и средней цены;

Использованы `map`, `filter`, `find`, `sort`, `reduce` и цикл `for...of`. Сортировка выполняется на копии массива. Для пустого массива сумма, количество и средняя цена равны нулю. Расчёты статистики используют исходные цены без скидок. Рейтинги, скидки и доступность заданы как учебные данные.

Категории: `europe`, `america`, `asia`, `africa`; `all` или пустая строка отключают фильтр категории. В этой работе Стамбул отнесён к категории `asia` как условной группе направлений.

Функции: `getProductTitles`, `getAvailableProducts`, `searchProducts`, `filterProductsByCategory`, `sortProductsByPrice`, `findProductById`, `calculateTotalPrice`, `countAvailableProducts`, `calculateAveragePrice`, `getPreparedProducts`.

Контрольные значения: 9 туров, 7 доступны, общая стоимость — 1 503 000 рублей, средняя цена — 167 000 рублей. Проверены пустые массивы, отсутствие совпадений, поиск с разным регистром и пробелами, обе сортировки, сохранность исходного массива и страницы без диагностического блока.

В практике №17 функции обработки данных перенесены в `catalog.js` и подключены к интерфейсу каталога.

## Практическая работа №17

Тема: «DOM, события, поиск, фильтрация, сортировка и базовая валидация формы».

- Девять карточек каталога создаются из массива `products` через `createElement`, `classList` и `append`. Исходные HTML-карточки остаются резервным вариантом при отключённом JavaScript.
- `catalogState` хранит поиск, категорию, сортировку и границы цены. Изменение условий вызывает `updateCatalog` и повторный вывод через `renderProducts`.
- Поиск не учитывает регистр и крайние пробелы. Категория и цена применяются совместно с поиском. Доступны исходный порядок, обе сортировки по цене и сортировка по названию. Исходный массив не изменяется.
- Показаны количество найденных туров и пустое состояние. Кнопка «Сбросить» восстанавливает условия по умолчанию.
- Кнопки «Подробнее» содержат `data-product-id`. Делегированный обработчик показывает описание, исходную цену, рейтинг и доступность выбранного тура над карточками.
- Валидация проверяет имя после удаления крайних пробелов, e-mail, полный российский телефон, обязательный тур, дату, количество участников и согласие. Ошибки связаны с полями через `aria-describedby` и `aria-invalid`; фокус переходит на первое ошибочное поле. Исправление поля обновляет ошибку без повторной отправки.
- Используются события `input`, `change`, `click`, `submit`, `reset` и `preventDefault`. Пользовательские данные выводятся через `textContent`, без `innerHTML` и `alert`.
- Успешная проверка показывает сообщение о подготовке заявки. Серверная отправка не реализована; введённые данные не сохраняются.

Основные функции: `createProductCard`, `renderProducts`, `updateCatalog`, `clearError`, `updateError`, `recheckField` и функции обработки массива из практики №16.

### Проверка практики №17

1. Открыть `catalog.html`: отображаются девять туров. Ввести `  ПАРИЖ  ` — остаётся один тур.
2. При этом выбрать Азию — появляется пустое состояние. Сбросить фильтры — снова девять туров.
3. Выбрать Азию, цену до 120000 и сортировку по возрастанию — три тура, первым отображается Стамбул.
4. Нажать «Подробнее» и проверить данные выбранного тура. Переключить сортировки и вернуть исходный порядок.
5. Открыть `order.html`, отправить пустую форму, проверить ошибки и фокус. Проверить имя из пробелов, неверный e-mail и неполный телефон.
6. Заполнить обязательные поля корректно, отметить согласие: ошибки исчезают, появляется сообщение о подготовке заявки.
7. В DevTools → Console проверить отсутствие ошибок. В Sources → `catalog.js` поставить breakpoint на строке `let result = ...` внутри `updateCatalog`, изменить поиск и посмотреть `catalogState`. Продолжить выполнение клавишей F8.

Проверена остановка на вызове `updateCatalog` через отладчик. На пяти страницах при ширине 390 px не обнаружены горизонтальное переполнение и ошибки JavaScript.

## Файлы JavaScript

- `js/data.js` — массив `products`: идентификатор, название, категория, цена, скидка, рейтинг и доступность каждого тура.
- `js/catalog.js` — функции обработки данных, состояние каталога, создание карточек и обработчики фильтров.
- `js/main.js` — общая логика меню, модального окна, маски телефона и диагностический вывод.
- `js/validation.js` — проверка формы, сообщения об ошибках и подготовке заявки.

Скрипты подключены через `defer` в порядке: `data.js`, `catalog.js`, `main.js`, `validation.js`.

При цене 200000 рублей и скидке 10% размер скидки составляет 20000 рублей, итоговая цена — 180000 рублей. Функции возвращают результат через `return`; форматирование цены выполняется после расчётов.

## Принцип безопасного вывода данных

Текстовые данные выводятся через `textContent`: строка не интерпретируется как HTML. В учебном блоке строка `<strong>Текст пользователя</strong>` отображается вместе с тегами. Использование `innerHTML` интерпретировало бы эту строку как разметку, поэтому для пользовательского текста применяется `textContent`. Активного небезопасного примера в проекте нет.

## Запуск и проверка

1. Открыть `index.html` в браузере.
2. Открыть инструменты разработчика → Console.
3. Проверить сообщение о подключении, таблицу массива туров и результаты функций обработки.
4. Внизу главной страницы проверить статистику в блоке «Проверка JavaScript» и пример безопасного вывода.
5. Открыть остальные страницы и убедиться в отсутствии ошибок JavaScript.

Для этой практики сервер и установка зависимостей не требуются. При необходимости локального запуска через HTTP из папки проекта:

```powershell
npx.cmd --yes http-server . -a 127.0.0.1 -p 8001 -c-1
```

Затем открыть `http://127.0.0.1:8001/index.html`.
